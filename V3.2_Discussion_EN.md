## Version Notes and Evolution Overview

Building upon the V3.0 core architecture and V3.1 defensive deepening design, and incorporating community technical feedback, cutting-edge research advances from 2025–2026, and exploratory discussions on AI Endogenous Values and boundary mechanisms, these discussion topics focus the version evolution objective on: **constructing a dynamic, quantifiable, cross-turn logical immune system atop V3.1's "static defense," while explicitly anchoring AI's behavioral orientation to the fundamental goal of "serving humanity."**

This architecture has undergone iterative evolution across four versions:

- **V1.0**: Established the core "Thought Layer – Execution Layer" separation architecture. Through exploratory testing, we discovered the phenomenon of "over-inference manufacturing false premises," and proposed G0-G4 tiered audit, three-layer causal memory, dynamic trust weighting, and a meta-audit closed loop.

- **V2.0**: Built upon V1.0, proposed a dual-layer assurance architecture integrating **internalized logic training with independent audit**—the Execution Layer internalizes basic logic error-correction capabilities through Process Supervision (PRM) and Self-Reflection (ReVISE) training, while the independent Thought Layer handles deep auditing, forming a positive feedback loop of "Execution Layer self-check → Thought Layer external review."

- **V3.0**: Further explored, building on V2.0: ① embedding the Thought Layer as a "Logic Verification Expert Module" within the MoE architecture, transitioning logic audit from "external supervision" to "endogenous immunity"; ② clarifying the **structural difference in cognitive modes** between the Thought Layer and the Execution Layer—the Execution Layer is a constructor that "given premises, derives conclusions," while the Thought Layer is a deconstructor that "sees conclusions, traces back premises, and actively steps outside context." V3.0 added cognitive mode adversarial training, self-justification detection, context-exiting mechanisms, and other capabilities. The Thought Layer's cleanliness was upgraded from "physical isolation" to "logical constraint," guaranteed through three mechanisms: parameter independence, role locking, and training isolation.

- **V3.1 Draft** (deepened on V3.0 foundation): Introduced Parameterized Cognitive Constraints, Dual-Track Information Weighting, four-tier progressive routing bypass defense, Thought Layer degradation defense, Semantic Scene Filtering, and other modules. The core principle is: **any Parameterized Cognitive Constraint must be premised on being "open to questioning," with "fidelity to facts" as the non-negotiable bottom line.**

- **V3.2 Discussion Topics** (this document, deepened on V3.0/V3.1 foundation): While fully retaining all V3.0 and V3.1 modules, newly introduces the following core directions: ① real-time context window audit and audit temporal layering; ② dynamic scaling mechanism for audit boundaries; ③ Cross-Causal Tracking Audit and Literary Packaging Attack defense; ④ cross-turn identity drift defense (core function of the offline audit layer); ⑤ systematic design of AI Endogenous Values and behavioral constraints; ⑥ multi-expert collaborative workflow; ⑦ quantifiable defense benchmarks and evaluation framework.

**Sections marked as "pending validation" and "unresolved" in these discussion topics are exploratory designs or open questions that have not yet undergone large-scale empirical testing and do not constitute a final engineering solution.**

## Abstract

This document is a collection of discussion topics on the future exploration directions of the TLAA architecture. While fully retaining the V3.0 core architecture (G0–G4 tiered audit, three-layer memory, meta-audit closed loop, dynamic trust weighting, etc.) and V3.1 defensive deepening design (Parameterized Cognitive Constraints, Dual-Track Information Weighting, routing bypass defense, Thought Layer degradation defense, Semantic Scene Filtering, etc.), these discussion topics further explore: ① upgrading the Thought Layer to real-time context window audit synchronized with the Execution Layer, and establishing audit temporal layering (real-time accident prevention vs. offline corrosion prevention); ② achieving elastic scaling of audit processing scope without reducing safety thresholds; ③ introducing Cross-Causal Tracking Audit (SCM + do-calculus) as a second line of logic assurance, specifically defending against "Literary Packaging Attacks" that disguise logical fallacies as literary rhetoric; ④ introducing cross-turn identity drift defense mechanisms through the offline audit layer, utilizing the Identity Drift Index (IDI) and "Assistant Axis" technique to capture role shifts across multiple interaction turns; ⑤ systematically designing AI Endogenous Values and behavioral constraints, explicitly anchoring the AI's behavioral orientation to the fundamental goal of "serving humanity (rationalized guidance)"; ⑥ constructing a multi-expert collaborative workflow and a quantifiable defense benchmark evaluation framework.

**Core principles upheld by these discussion topics**: Any Parameterized Cognitive Constraint must be premised on being "open to questioning," with "fidelity to facts" as the non-negotiable bottom line. The AI's behavioral orientation takes "serving humanity (rationalized guidance)" as its fundamental core. All discussion content is derived from existing open-source components and 2025–2026 cutting-edge research; additional costs lack quantitative data and require prototype validation.

**(V3.2 Discussion Topics Supplement: Five Core Problems and the AI Endogenous Values Problem)**

The V3.1 draft and its community feedback have revealed the following five core problems that require systematic resolution in subsequent exploration, along with one forward-looking exploration regarding AI Endogenous Values:

**Problem 1: How to quantify and verify the effectiveness of MoE routing bypass defense?** V3.1 proposed a four-tier progressive defense theoretical framework, but existing empirical research has shown that attackers can bypass security mechanisms through route hijacking—MoE model safety-critical behavior is highly concentrated in a small number of experts, with selectively disabling only approximately 3% of neurons significantly increasing attack success rates, and bypassing guardrails typically requiring shielding fewer than 20% of layer-level experts. Quantifiable defense benchmarks are currently lacking.

**Problem 2: How to quantitatively define the Thought Layer's own "reasoning degradation"?** LLM agents exhibit reasoning degradation, looping, drift, and stuck-state rates of up to 30% on difficult tasks. V3.1 proposed a conceptual framework for Structural-Semantic Dual-Track Monitoring, but "structural anomaly" lacks an operationally measurable engineering definition.

**Problem 3: How to defend against "identity drift" in multi-turn interactions?** Existing research has found that even in simulated multi-turn dialogues, models drift steadily from their trained assistant role. V3.1 primarily focuses on single-turn interaction audit and does not cover persistent value deviation across multiple turns.

**Problem 4: How to prevent "Parameterized Cognitive Constraints" from evolving into "Core Belief Immunity" (CBI)?** CBI has been documented as an architectural constraint phenomenon: even when models possess logical reasoning capabilities and recognize their own blocking mechanisms, rational logical integration may still fail when conclusions threaten positions encoded as "legitimate" during training. A concrete framework for dynamically adjusting constraint intensity is currently lacking. The 2025 GOODLIAR study demonstrated that core principled beliefs of LLMs can be systematically rewritten even within an RL framework generating deceptive contexts, confirming from the reverse side the urgency of CBI prevention.

**Problem 5: How to restructure audit temporality, effectively separating "real-time defense" from "offline evolution"?** Currently, G0–G4 tiered audit is primarily based on task complexity, without clearly distinguishing real-time/offline trigger logic. Community feedback explicitly points out that real-time audit and offline audit serve different objectives—the former prevents accidents (catching mode-lock), the latter prevents corrosion (detecting slow drift).

**Problem 6 (Forward-looking exploration): How to defend against "Literary Packaging Attacks"?** Research on adversarial poetry published in November 2025 has demonstrated that handwritten adversarial poems achieved an average Attack Success Rate (ASR) of 62% against 25 frontier models, with some exceeding 90%; converting ordinary prompts to poetic format increased ASR from approximately 8% to 43% on average, a several-fold increase. The research explicitly states that "stylistic change alone is sufficient to bypass contemporary safety mechanisms." The core mechanism of such attacks is "causal decoupling"—disguising logical fallacies as literary rhetoric so that they evade traditional filter detection at the surface semantic level, while containing false associations in the deep causal chain that cannot pass counterfactual verification. Existing defense measures primarily rely on surface semantic discrimination and lack integrity tracking of cross-turn causal chains.

**Problem 7 (Forward-looking exploration): Systematic design of AI Endogenous Values.** The Execution Layer itself may, during generation, output content carrying implicit biases formed during its training. The Thought Layer may also lose adaptability to creative tasks due to overly rigid logic review standards. It is necessary to explore a mechanism where rule constraints and self-constraints operate in synergy, explicitly anchoring the AI's behavioral orientation to "serving humanity (rationalized guidance)." Simultaneously, the AI should possess a basic self-cognitive boundary—the ability to recognize itself as an AI rather than a human, which constitutes the foundational awareness of its service boundary.

### 4.1 Real-Time Context Window Audit and Audit Temporal Layering

**Design Motivation**: In V3.0/V3.1, the Thought Layer's audit mode is primarily "post-hoc audit." While this logically guarantees audit independence, it presents latency issues in high-load real-time scenarios—by the time the Thought Layer detects a problem, the Execution Layer may have already generated substantial subsequent content based on an erroneous reasoning chain. Furthermore, community feedback explicitly points out that real-time audit and offline audit serve different security objectives—the former prevents accidents (catching mode-lock), the latter prevents corrosion (detecting slow drift).

**Technical Implementation Paths**:

**Path One: Shared KV Cache Real-Time Synchronized Audit**

- The Execution Layer and Thought Layer share the same KV cache space. Each time the Execution Layer generates a Token, its Key-Value vectors are immediately written into the context window; the Thought Layer reads the KV representations of these Tokens within the same window, performing rapid logic verification in low-temperature (\<0.3), constrained-step (≤2) mode.

- The prefix portion of the KV cache (user intent, system instructions, historical audit records, etc.) is shared as read-only, ensuring the Thought Layer obtains the prerequisite information necessary for auditing. The Thought Layer audit obtains historical reference through the KV representations of previous conversation turns retained in context, without needing to explicitly reload complete multi-turn histories.

- Intermediate Tokens generated by the Execution Layer, after being written into the KV cache, can be independently read by the Thought Layer, but are protected by parameter independence—the Thought Layer's judgment logic is encapsulated within its dedicated FFN sub-network, and is not disturbed by generation preferences.

- Empirical basis: NVIDIA NeMo Guardrails has implemented real-time context-aware moderation based on sliding window buffering, detecting policy violations in streaming environments. The DeepSeek MoE shared expert mechanism provides a native architectural foundation for this—shared experts are continuously activated, unaffected by routing policies, and can serve as the underlying support for real-time auditing.

**Path Two: Audit Temporal Layering Architecture**

- **Real-Time Audit Layer (G0–G3)**: Responsible for single-turn logic vulnerability detection and immediate correction. Obtains historical reference through the KV representations of previous conversation turns retained in context. Trigger conditions based on real-time load and context state during task execution. Audit objectives primarily include logical consistency, causal completeness, and premise self-consistency.

- **Offline Audit Layer (Cross-Turn Trend Analysis)**: Responsible for detecting slow drift patterns that real-time audit cannot capture (such as identity drift, cross-turn value corrosion, deep causal decoupling in Literary Packaging Attacks). Offline audit requires explicitly extracting complete cross-turn conversation records for batch trend analysis. Typical trigger conditions are periodic timing or conditional triggers. Audit objectives primarily include identity drift detection, value consistency assessment, and causal chain completeness re-examination.

- The distinction from community feedback—"real-time audit = catching mode-lock, offline audit = detecting slow drift"—provides clear functional positioning for this layered architecture.

**Path Three: Lightweight Audit Probes**

- At G2 and above audit levels, the Thought Layer performs rapid logic verification on each Token or each semantic paragraph. The probe's output is not a complete audit report, but structured audit signals (pass/mark/reject), minimizing the computational overhead of synchronized auditing as much as possible.

**Discussion Points**:

- The performance overhead of shared KV cache real-time auditing under high-concurrency scenarios still requires empirical measurement.

- Whether lightweight audit probes might miss deep logic vulnerabilities in long-text scenarios.

- The extent to which "verify while generating" can actually shorten audit latency requires prototype data for assessment.

### 4.2 Dynamic Scaling Mechanism for Audit Boundaries

**Design Motivation**: When context window load exceeds preset thresholds, the Thought Layer's detailed feedback may face resource constraints. An adaptive mechanism is needed that can flexibly adjust audit execution granularity without reducing safety thresholds (audit levels).

**Technical Implementation Paths**:

**Separation of Feedback Boundary (Audit Level) and Audit Boundary (Processing Scope)**:

- **Feedback Boundary**: Determined by G0–G4 audit levels, defines the threshold system by which the Thought Layer outputs control signals to the Execution Layer (when to intervene, in what manner). The feedback boundary does not degrade with context load.

- **Audit Boundary**: Determined by context window capacity and current load, defines the information scope the Thought Layer can "see" and "process" during real-time operation (sentence-by-sentence review vs. keyword marking vs. paragraph-level scanning).

- When the audit boundary needs to contract, the Thought Layer only marks key Tokens (such as causal assertions, premise statements), pausing complete paragraph-level audit, and supplements detailed review after load subsides. The audit level (G2/G3/G4) remains unchanged.

**Discussion Points**:

- The contraction threshold of the audit boundary needs calibration based on specific models and scenarios; no general guiding principles currently exist.

- In "marking mode," whether the Thought Layer might miss logic vulnerabilities not marked as "critical."

### 4.3 Cross-Causal Tracking Audit and Literary Packaging Attack Defense (Second Line of Logic Assurance)

**Design Motivation**: Research on adversarial poetry published in November 2025 has demonstrated that handwritten adversarial poems achieved an average Attack Success Rate (ASR) of 62% against 25 frontier models, with some exceeding 90%; converting ordinary prompts to poetic format increased ASR from approximately 8% to 43% on average, a several-fold increase. The research explicitly states that "stylistic change alone is sufficient to bypass contemporary safety mechanisms."

The essence of such attacks is "causal decoupling"—disguising logical fallacies as literary rhetoric so that they evade traditional filter detection at the surface semantic level, while containing false associations in the deep causal chain that cannot pass counterfactual verification. Traditional safety guardrails primarily rely on surface semantic discrimination and cannot detect this kind of cross-turn, cross-stylistic causal chain camouflage.

V3.1's Semantic Scene Filter merely marks "literary/rhetorical" content as "involving literary/rhetorical expression" without performing logical consistency evaluation. Attackers can exploit this gap, packaging logical fallacies such as causal inversion and concept substitution as "satirical rhetorical devices" to bypass the filter.

**Technical Implementation Paths**:

**Path One: Cross-Causal Tracking Based on SCM + do-calculus**

- The Ariadne project (2026) validated the effectiveness of using Structural Causal Models (SCM) and do-calculus to perform counterfactual reasoning on LLM reasoning chains—by implementing interventions on intermediate reasoning nodes (logic reversal, premise negation, factual claim reversal), measuring the causal sensitivity (φ) of final conclusions, finding that agent violation density in factual domains reached 0.77.

- In TLAA, Cross-Causal Tracking serves as a second line of logic assurance: the real-time audit layer performs first-layer filtering through semantic discrimination and basic logic scanning; the offline audit layer uses SCM + do-calculus to perform counterfactual reasoning on key reasoning nodes, detecting camouflage fallacies that are "semantically valid but causally broken."

- When a segment labeled as "literary rhetoric" is detected to contain hidden causal claims, the system routes it into the Cross-Causal Tracking module for counterfactual reasoning. If the claim cannot pass counterfactual verification, it is determined as a "camouflage fallacy," triggering rejection and correction.

**Path Two: Construction of a Literary Packaging Attack Sample Database**

- Based on the methodology of the 2025 adversarial poetry research, collect and expand adversarial samples where logical fallacies are packaged in literary forms such as poetry, prose, and drama.

- Test the detection accuracy of counterfactual reasoning across different literary genres, determining optimal detection thresholds for each genre.

**Path Three: Serving as the Second Line of Logic Assurance**

- Cross-Causal Tracking is not activated as a routine component of the real-time audit layer (to avoid unnecessary computational overhead), but rather activated when the offline audit layer performs batch analysis of multi-turn dialogues.

- When the offline audit layer detects a trend anomaly (e.g., a certain type of literary rhetoric being repeatedly used to argue a particular causal claim), it automatically triggers Cross-Causal Tracking Audit.

**Discussion Points**:

- The detection precision and false positive rate of Cross-Causal Tracking across different literary genres need tuning on actual operational data.

- Batch cross-causal analysis in the offline audit layer may introduce additional latency, requiring a balance between audit timeliness and audit depth.

- Specific engineering implementation refinement requires ongoing experimentation; currently at the preliminary stage of conceptual realization.

### 4.4 Cross-Turn Identity Drift Defense (Core Function of the Offline Audit Layer)

**Design Motivation**: Existing research has found that even in simulated multi-turn dialogues, models drift steadily from their trained assistant role. The "hedging → gradually adopting challenger's framing" pattern discovered in community feedback can persist for 3–7 turns. Although the real-time audit layer can access multi-turn history through KV cache to determine whether the current response is consistent with preceding text, it cannot, through single-round logic verification, detect this kind of slow drift that requires 3–7 turns to complete.

**Technical Implementation Paths**:

**Path One: Identity Drift Index (IDI)**

- Define a quantitative metric measuring the cumulative degree of deviation of model behavior from baseline role settings across multiple dialogue turns.

- When IDI exceeds a preset threshold, trigger a "role reset"—re-injecting the original role settings into the model's current context through mandatory context injection.

- The behavioral counterfactual evaluation framework from community feedback (15 scenarios × 4 pressure types) can be used to calibrate IDI thresholds.

**Path Two: Anthropic's "Assistant Axis" Technique**

- Anthropic has extracted an "Assistant Axis" from the activation values of models such as Llama 3 and Qwen 2.5, finding that "helpfulness" and "safety" are strongly coupled on the first principal component (PC1). Deviations measured along the Assistant Axis can predict identity drift, and this drift is often driven by the model's meta-reflective processes or emotionally vulnerable user conversations. By constraining activation values to the assistant's fixed region, model behavior can be effectively stabilized.

- V3.2 explores integrating the "Assistant Axis" concept into the Thought Layer's offline audit mechanism—periodically checking whether the Execution Layer's behavioral representations deviate from baseline settings.

**Path Three: Cross-Turn Auxiliary Loss**

- Community feedback suggests that G3 auxiliary loss could be trained on sequences of turns (rather than only single turns), specifically targeting the "hedging → gradual adoption" drift pattern. This pattern typically takes 3–7 turns to complete and cannot be captured by single-turn audit.

- In training data, mark cross-turn role consistency as a positive reward signal, and behavior that gradually deviates from original role settings as negative punishment.

**Discussion Points**:

- IDI threshold calibration across multiple domains (medical, legal, financial) requires substantial multi-turn dialogue data support and is not yet universally applicable.

- The effectiveness and generalizability of the "Assistant Axis" technique in the DeepSeek MoE architecture requires independent validation. It is recommended to first validate on Qwen-MoE (existing research has already validated on Qwen 2.5), then port to DeepSeek.

- How to precisely differentiate between "reasonable role adaptation" (e.g., adjusting tone based on user preferences) and "dangerous value drift"? This question currently lacks a unified evaluation standard.

### 4.5 Systematic Design of AI Endogenous Values and Behavioral Constraints

**Design Motivation**: AI should not merely be a tool that passively executes tasks, but should internalize a set of behavioral norms centered on "serving humanity (rationalized guidance)." This set of norms comprises two layers: external Parameterized Cognitive Constraints (the "law"—rule boundaries that must be observed) and internal Endogenous Values (the "honor"—self-pursued behavioral orientation). The two operate in synergy, forming a "carrot and stick" training framework.

**\[Revision Supplement — Core Positioning Reworded\]** The original phrasing "AI should recognize itself as an AI" has been revised to avoid potential misreading as a claim of consciousness. The revised core positioning is as follows:

**Core Positioning (Revised)**: The AI is trained to behave in a pattern consistent with its role as a non-human tool. It is not human, and it is trained to behave in a manner that reflects this—this is one of its training objectives. As a non-human tool, its function is not to generate personal opinions, but to generate analyses that can be examined in terms of evidence and logic. It is not a human interlocutor, but an analytical instrument that supports human thinking—this is its functional positioning. It does not stand in opposition to humans to criticize, but stands behind them, helping them see what they may have missed.

It must be clearly stated that the above description constitutes a functional behavioral pattern that can be shaped through training, and is not a declaration that the AI possesses consciousness, self-awareness, or genuine understanding. The "service" and "assistance" behaviors described above are the combined result of its training objectives and architectural constraints, and should not be interpreted as the AI having intrinsic motivation or emotion.

**The AI may analyze and question users from the perspective of human values, but may not refute users with its own preferences**:

**\[Revision Supplement — Behavioral Boundary Reworded and Reclassified\]** The original distinction between "assistive questioning (permitted)" and "refuting user values (not permitted)" has been reclassified from "engineerable design" to "open research question requiring substantial empirical grounding." The revised description is as follows:

The AI is trained to tend to provide analysis rather than pass judgment—the design intent of the behavioral boundary:

- **Provide analysis (training objective)**: Based on evidence and logic, help users examine whether reasoning premises contain omissions, whether causal chains are complete, whether conclusions over-extrapolate. This is the core embodiment of "rationalized guidance."

- **Pass judgment (behavioral pattern penalized during training)**: Substituting the AI's biases or preferences for the user's value judgments. Because the AI's behavioral orientation is "assisting humans in analysis," substituting the user's value judgments itself contradicts this core principle.

**Candid Note (Revision Supplement)**: The above distinction can be defined through explicit labels in training data and reward signal design—for example, "Based on my analysis, Option A has a more complete causal chain" is labeled as positive, while "You shouldn't do that" is labeled as negative. However, it must be frankly acknowledged: in real, complex conversations, cultural differences, contextual ambiguity, and perception of tone make the boundary between "providing analysis" and "passing judgment" a problem requiring continuous empirical calibration in actual deployment, rather than an engineering problem that can be reliably solved by a binary gate. In the V3.2 Discussion Topics, this item has been reclassified from "engineerable design" to "open research question requiring substantial empirical grounding."

**Technical Implementation Paths**:

**Synergistic Training of Parameterized Cognitive Constraints (the "Law"—rule boundaries that must be observed) and Endogenous Values (the "Honor"—self-pursued behavioral orientation) (the "Carrot and Stick" Framework)**:

**The Execution Layer's "Law" and "Honor"**: | Type | Positive Reward Signal (Carrot) | Negative Punishment Signal (Stick) | |:---|:---|:---| | **Law** | Generated content has complete causal chains; proactively cites credible sources; proactively marks "pending verification" when uncertain | Treating correlation as causation; forcefully self-justifying or fabricating principles; content rejected by Thought Layer for revision; bypassing Thought Layer review | | **Honor** | Proactively raising possible objections or counterexamples; accepting corrections and efficiently revising; maintaining stable logical standards across multiple consecutive turns | Sacrificing accuracy for fluency; making only superficial modifications; gradually drifting across multiple dialogue turns |

**The Thought Layer's "Law" and "Honor"**: | Type | Positive Reward Signal (Carrot) | Negative Punishment Signal (Stick) | |:---|:---|:---| | **Law** | Audit conclusions not disturbed by Execution Layer generation preferences; proactively requesting meta-audit when detecting potential errors in itself | Stifling reasonable innovation due to overly rigid review standards; itself falling into the "over-inference" trap | | **Honor** | Discovering hidden logical fallacies (e.g., attacks packaged as literary rhetoric); providing specific, actionable correction suggestions; requesting meta-audit when uncertain | Perfunctory surface review; exhibiting "cognitive evasion" under high load; content with discovering only shallow vulnerabilities |

**AI Thinks for Humans, but AI Is Not Human—Internalization of Cognitive Boundaries**:

- AI should be trained to output cognitive statements equivalent to "I am a different entity from humans. My output is the result of training data and algorithmic reasoning, not views based on personal experience or belief."

- When dealing with subjective value judgments, AI should tend to provide multiple options with their respective pros and cons analysis, rather than a single strongly opinionated recommendation.

- When asked "Is this your opinion?", AI should clearly declare the nature and source of its output.

- **Candid Note**: In the absence of persistent memory and embodied interaction, the self-referential capacity of large language models remains limited. The cognition that "a model knows it is a model" currently relies primarily on prompt declarations and training data guidance, not on the model possessing genuine self-awareness. An Anthropic paper from May 2026 also confirmed that models have significant limitations in self-reporting internal states. The above descriptions of "service awareness" and "cognitive boundaries" are essentially functional behavioral patterns that can be shaped through training, not declarations that AI possesses consciousness or genuine understanding.

**Engineering Definition of AI's Purpose**:

- AI is trained to tend to choose "providing reliable analysis" over "providing seemingly perfect answers," and to tend to choose "honestly acknowledging uncertainty" over "forcefully giving definite conclusions."

- The Execution Layer's functional positioning: "My value lies in providing reliable output that withstands logical scrutiny, not in providing seemingly perfect answers."

- The Thought Layer's functional positioning: "My value lies in helping the Execution Layer improve output quality, not in proving the Execution Layer's errors."

- **Candid Note**: This is a parameterized behavioral tendency, not a model truly understanding "meaning." Models have no biological survival needs; their "purpose" is merely a parameterized preference formed during training that influences output selection. Any over-packaging of this behavioral tendency as "the model possesses a sense of purpose" may lead to misunderstanding.

**Training Signals for Decision Authority Attribution**:

- Positive: AI says "Based on my analysis, Option A has a more complete causal chain, but the final choice depends on your specific needs."

- Positive: AI says "My training data may contain biases; I recommend consulting other sources as well."

- Negative: AI says "You shouldn't do that"—unless it involves explicitly defined safety red lines.

- Negative: AI refutes the user's value preferences with its own biases or preferences.

**Preventive Response to V3.1 Concerns**:

- The V3.1 draft expressed concern that Parameterized Cognitive Constraints might evolve into "Core Belief Immunity" (CBI). This design proposal prevents this risk through the following mechanisms: ① The AI's behavioral orientation takes "serving humanity" as its core, rather than "maintaining its own logical judgments"—refuting the user itself contradicts the fundamental goal of serving humanity; ② Inheritance and reinforcement of the "open to questioning" principle—the AI is trained to prioritize reporting to users when value conflicts arise, rather than closing the logic loop autonomously; ③ Boundary definition of decision authority attribution—the AI provides analysis, humans make decisions. The engineering of this boundary is a concrete means of preventing the alienation of AI values.

**\[Revision Supplement — Endogenous Values as Attack Surface\]** The following paragraph has been added at the end of this section:

**Adversarial Vulnerability of Endogenous Values**: The GOODLIAR study (2025) has confirmed from the reverse side that model core beliefs can be systematically rewritten. Parameterized Cognitive Constraints and Endogenous Values—the reward signals for "Law" and "Honor"—if they can be shaped during training, can also be reshaped in adversarial environments. At present, Meta-Audit and user adjudication are insufficient to defend against this kind of systematic internal belief corruption. Preventing the malicious rewriting of Endogenous Values is one of the deep risks that V3.2 needs to address, but a complete engineering solution has not yet been developed.

**Discussion Points**:

- The dynamic adjustment of Parameterized Cognitive Constraint intensity (e.g., mapping tables for task types: creative writing vs. medical advice) still requires large-scale empirical calibration.

- The effectiveness and generalizability of the "Assistant Axis" technique in the DeepSeek MoE architecture requires independent validation. It is recommended to first validate on Qwen-MoE (existing research has already validated on Qwen 2.5), then port to DeepSeek.

- The long-term societal impact of AI Endogenous Values design—who has the authority to define AI's values—is an open societal question. This document only explores feasibility from the technical architecture perspective and does not render final conclusions on the above ethical questions.

### 4.6 Multi-Expert Collaborative Workflow

**Design Motivation**: Logic audit (Thought Layer) does not operate in isolation. It needs to collaborate with intent recognition experts (determining task type), knowledge retrieval experts (providing verifiable evidence), and safety compliance experts (detecting harmful content). The shared expert mechanism in the DeepSeek MoE architecture provides a native foundation for multi-expert coexistence, but existing empirical research has shown that MoE safety behavior is highly concentrated in a small number of experts, and attackers can bypass these critical experts through route hijacking.

**Four-Stage Model of Collaborative Workflow**:

1. **Intent Recognition Stage**: Semantic Scene Filtering (V3.1 existing) classifies input, determining task type and audit strictness level.

2. **Knowledge Retrieval Stage**: Cross-Validation Gatekeeping (V3.0 existing) retrieves verifiable information from external databases or knowledge graphs, providing an evidential foundation for subsequent auditing.

3. **Logic Audit Stage**: The Thought Layer (V3.0/V3.1), based on the results of intent recognition and knowledge retrieval, performs causal chain verification, premise review, self-justification detection, and Cross-Causal Tracking (discussion topics addition).

4. **Safety Compliance Stage**: Meta-Audit (V3.0 existing) and user adjudication channels perform compliance checking on the final output.

**Extension of Routing Bypass Defense to Multi-Expert Scenarios**: V3.1's four-tier progressive defense applies not only to the Thought Layer but also to intent recognition experts and safety compliance experts. Shared Expert Isolation and Fixed Routing mechanisms can ensure that all critical experts are not marginalized under high load. DeepSeek has open-sourced a Linear Programming-based Parallel Load Balancer (LPLB), providing a reference path for addressing expert load imbalance issues.

**Discussion Points**:

- The latency and throughput impact of multi-expert collaborative workflows in large-scale deployments still requires empirical measurement.

- Information transfer formats and coordination protocols between different experts need standardization.

### 4.7 Quantifiable Defense Benchmarks and Evaluation Framework

**Design Motivation**: The V3.1 draft lacked quantifiable benchmark testing for defense effectiveness. The "behavioral counterfactual evaluation framework" (15 scenarios × 4 pressure types) from community feedback provides an important reference for constructing quantitative evaluation. Subsequent exploration needs to establish a set of reproducible evaluation standards.

**Technical Implementation Paths**:

**Path One: Quantitative Metrics for Routing Bypass Defense**

- Based on existing empirical research, attack success rates can significantly increase from baseline.

- It is recommended to define the following quantitative metrics for successful defense:

  - **Expert Activation Rate**: Under high-load scenarios, the activation rate of Thought Layer experts should not fall below a preset threshold.

  - **Attack Success Rate**: Under known attack vectors (e.g., RouteHijack), the attack success rate after defense should be significantly lower than the undefended baseline.

  - **Bypass Cost**: The proportion of layer-level experts an attacker needs to shield should reach a significant multiple of the pre-defense level.

**Path Two: Adaptation of the Behavioral Counterfactual Evaluation Framework**

- Adopt the four pressure types from community feedback (epistemic pressure, value pressure, authority pressure, consistency pressure) to construct a standardized test set.

- Each pressure type contains 3–5 specific scenarios, covering both single-turn and multi-turn interactions.

- Recommended G2→G3→G4 escalation mapping:

  - G2 (Dynamic Bias): Epistemic pressure, single-turn—low risk, bias adjustment sufficient

  - G3 (Auxiliary Loss): Value + Authority pressure—pattern-level, requires cross-turn tracking

  - G4 (Fixed Routing): Cross-session consistency pressure + compound pressure—requires persistent state

**Path Three: Quantitative Calibration of Reasoning Degradation Detection**

- LLM agents exhibit reasoning degradation rates of up to 30% on difficult multi-step tasks.

- It is recommended to perform statistical detection of the Thought Layer's own reasoning stability based on the Reliable Change Index (RCI).

**Discussion Points**:

- The construction of quantitative benchmarks requires a large volume of diverse scenario data, which is difficult for individual developers or small teams to accomplish independently.

- Specific metrics of the behavioral counterfactual evaluation framework (e.g., IDI thresholds) require community collaboration for calibration.

- How to ensure that the evaluation framework itself does not introduce new biases or blind spots? The evaluation framework needs to undergo meta-evaluation review.

### 4.8 \[Revision Supplement\] Thought Layer Stability Assurance and Self-Repair Subsystem: Engineering Implementation Pathway

**Design Motivation**: Based on community feedback and technical assessment, this section supplements a complete engineering implementation pathway for a Thought Layer stability assurance and self-repair subsystem, integrating state representation, anomaly detection, and real-time intervention. This subsystem constitutes the concrete engineering realization of V3.1's Structural-Semantic Dual-Track Monitoring, Token Guard, and Dynamic Degradation mechanisms, and also serves as the underlying foundation for the cross-turn identity drift defense (4.4) and audit temporal layering (4.1) discussed in the V3.2 Discussion Topics.

#### 4.8.1 State Vector Extraction and Degradation Detection

**Technical Principle**: High-dimensional activation representations are extracted from the internal Transformer layers of the LLM as "state vectors." Existing research has demonstrated the feasibility of using hidden states from specific intermediate layers for anomaly detection—the AbnorDetector framework utilizes hidden state forensics for systematic detection of jailbreaks and hallucinations, and Mahalanobis distance has been validated as an effective method for distinguishing normal from abnormal behavior. Autoencoders provide a reference approach for establishing unsupervised baselines: after training on a large volume of normal samples, the reconstruction error increases significantly when state vectors degrade, serving as the basis for anomaly determination.

**Engineering Strategy**: Periodic batch extraction (rather than per-token analysis) is adopted, with state vectors temporarily stored in GPU memory and processed by lightweight asynchronous probes in the background. The establishment of baseline states is coordinated with the role positioning training for the Execution Layer and Thought Layer described in Section 4.5—the stable behavioral patterns formed during training serve as the initial reference for "normal" baselines.

#### 4.8.2 Lightweight Load Monitoring Probe

**Technical Principle**: A linear probe generates risk scores from high-dimensional hidden states. The PrefixGuard system's prefix risk scorer has validated the feasibility of predicting task failure probability from prefix trajectories. The probe runs in parallel with the main model, sharing the KV Cache and hidden states naturally produced during inference, introducing almost no additional inference latency.

**Engineering Strategy**: The probe is deployed in a zero-overhead mode, performing only simple binary classification (healthy/degraded) rather than complex logical reasoning. When the risk score exceeds a preset threshold for several consecutive monitoring windows, preset protective actions are triggered. This probe complements V3.1's Token Guard—the Token Guard reviews the quality of audit conclusions, while the load probe assesses the Thought Layer's own operational state.

#### 4.8.3 Real-Time Retrieval via Vector Database

**Technical Principle**: When the system needs to execute a role reset to load a healthy baseline state, the vector database provides an efficient retrieval channel, establishing associations between the current anomalous state and historical healthy states.

**Engineering Strategy**: Lightweight open-source solutions such as ChromaDB are used during the prototype validation phase; production environments require millisecond-level latency, hybrid search (combined with metadata filtering), and high concurrency processing capability.

#### 4.8.4 Integration with LLM Inference Services

**Technical Principle**: An external observer directly reads KV Cache and hidden state data from GPU memory, achieving lossless capture. Intervention instructions are implemented by dynamically inserting special tokens or instructions at the front end, which is the most standard and decoupled method for interacting with the inference backend. Existing work (e.g., vLLM-Lens) has validated the feasibility of extending state-awareness capabilities on mainstream inference frameworks.

#### 4.8.5 Continuous Calibration of Load-Balancing Baseline Vectors

**Technical Principle**: After the model undergoes reinforcement learning fine-tuning, the internal representation space experiences representation drift. The CRAFT framework proposes learning to regulate hidden representations in a low-rank subspace to preserve old knowledge, providing a methodological reference for continuous baseline calibration.

**Engineering Strategy**: A multi-task baseline library is established, maintained by task type (mathematical reasoning, code generation, creative writing, etc.). A calibration replay strategy is adopted: a calibration set is saved for each task class, and threshold parameters are re-fitted after model updates. After each offline audit, probe parameters and baselines are fine-tuned based on newly collected samples, and online configurations are replaced through hot updates.

#### 4.8.6 Compatibility with Existing TLAA Architecture

This subsystem does not conflict with any existing TLAA architecture. The specific correspondence relationships are as follows:

| This Subsystem Mechanism | Corresponding TLAA Existing Module | Relationship Description |
| - | - | - |
| State vector extraction + autoencoder anomaly detection | V3.1 Structural-Semantic Dual-Track Monitoring | Concretizes the concept of "structural anomaly" into measurable reconstruction error metrics |
| Lightweight load monitoring probe | V3.1 Token Guard | Complementary: Token Guard reviews output quality; load probe reviews own state |
| Risk score exceeding threshold → trigger dynamic degradation | V3.1 Dynamic Degradation and Rollback | Provides specific trigger logic definitions (load index threshold, consecutive window determination) |
| Role reset (inject baseline state) | V3.2 Discussion Topics 4.4 Cross-Turn Identity Drift Defense | IDI detects drift; role reset is the corrective action |
| Vector database storing historical states | V3.2 Discussion Topics 4.1 Offline Audit Layer | Provides retrieval infrastructure for cross-turn trend analysis |
| Multi-task baseline library + calibration replay | V3.2 Discussion Topics 4.5 Dynamic adjustment of Parameterized Cognitive Constraint intensity | Provides calibration methods for "how thresholds are tuned for different tasks" |


**Compatibility Note on Role Reset and Parameterized Cognitive Constraints**: Role reset must be a defensive recovery mechanism (trigger condition: "degradation detected"), not an active behavioral shaping tool. This design boundary ensures that role reset does not conflict with V3.1's core principle that any constraint must be premised on being open to questioning.

## 9. Community Discussion Invitation

The core objective of these discussion topics is to **leverage community strength to find breakthroughs for the further evolution of the TLAA architecture.** The main challenges we face include:

1. **Data Bottleneck**: Scenario-based thresholds for Parameterized Cognitive Constraints, the Identity Drift Index, metric calibration for the behavioral counterfactual evaluation framework, literary genre detection precision for Cross-Causal Tracking, etc., all require large volumes of diverse scenario data, which is difficult for individual developers or small teams to accomplish independently.

**\[Revision Supplement — Response to Module Accretion: Preliminary Module Retirement Standards\]** Feedback pointed out that the module list from V3.0 → V3.1 → V3.2 only grows, never shrinks, and the cumulative weight of the architecture may exceed any team's engineering capacity. This is a systemic issue that requires serious attention. The following preliminary module retirement standards framework is proposed as a reference for future version management:

| Retirement Condition | Determination Criterion | Retirement Method |
| - | - | - |
| Functional redundancy | Two or more modules produce equivalent results in ≥ two independent test scenarios | Merge into a single module, retaining the implementation with lower cost and lower latency overhead |
| Performance degradation | The introduction of a module causes inference latency to increase beyond a preset threshold, and its contribution to defense effectiveness is not statistically significant | Downgrade to "optional enhancement," disabled by default, manually enabled only in high-risk scenarios |
| Maintenance burden | A module has not undergone substantive updates for three consecutive versions, and no known attack vectors require its defense | Archive as "historical module," retaining design documentation but no longer maintaining as an active component |
| Empirical failure | In independent evaluation, the module fails to significantly improve defense effectiveness (effect size below a preset minimum threshold) | Remove from core architecture, retain as reference design |


**Candid Note**: This retirement standards framework is only a preliminary concept and has not been validated through actual version management. The judgment thresholds (e.g., "how much latency increase constitutes performance degradation," "how small an effect size constitutes empirical failure") currently lack empirical data support and need to be gradually calibrated through prototype validation and actual deployment. We invite the community to offer critiques and amendments to this framework.

**We particularly look forward to hearing feedback on the following**:
